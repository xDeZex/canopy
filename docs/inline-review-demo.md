# Read-only inline reviews: user evaluation

**The USER, never an agent, must perform the visual and accessibility checks below.** Automated checks use fake filesystem IO, DOM and public Monaco controllers; they do not prove native rendering, selection, folding, focus or screen-reader behavior. Agents must not browser-verify this feature.

## Set up the manual fixture

In a disposable **registered Git worktree** of this repository, manually create `.canopy/` and copy `docs/fixtures/comments.yaml` to `.canopy/comments.yaml`. Do not overwrite an existing conversation file. Start Canopy as described in the README and select that worktree.

This exercises the shipped path: fixed sidecar → registered `/api/comments` read route → workspace-local resource → sidebar index → main conversation view or actual Monaco inline rail. The two valid fixture threads share a rail below line 34 of `public/app.js` in File and Diff. A true general conversation, a missing-file conversation and an out-of-range conversation exercise the distinct navigation paths.

Canopy only writes this file when you save a new line or line-range comment (see below). There are no reply/Edit/Resolve buttons or vendor hooks. You may point an arbitrary agent at the file manually, outside Canopy. No agent-instruction files need changing. This repository ignores `.canopy/`, keeping worktree-local conversations out of its commits; Canopy itself never edits ignore files. Worktree deletion deletes its sidecar along with other files, subject to Canopy's existing deletion confirmation.

## Schema and reload contract

Version 1 has exactly two thread shapes:

- **Anchored (unchanged):** `{id, file, side: modified, line_range: {start, end}, created_at, resolved, messages}`.
- **General:** `{id, created_at, resolved, messages}`. Omit `file`, `side` and `line_range` completely; do not use null values. Unavailable anchors remain anchored, never general.

Each message has exactly `{id, author: user|agent, text, created_at}`. IDs and ISO timestamps with timezone are preserved; thread/message chronology is sorted by creation timestamp (stable input order for equal timestamps). Thread IDs are unique within the sidecar and message IDs within their conversation. Ranges are inclusive, 1-based, modified-side only. Unknown fields, partial/null anchors, invalid schema, duplicate IDs, unsupported versions, YAML parser errors/warnings, and non-Core tags reject the whole sidecar with a visible warning. Message text is plain text, not Markdown or HTML.

Relative anchor paths cannot contain empty/dot/traversal segments, absolute paths, colons, backslashes or control characters. All symlinked path components are conservatively rejected, even links staying inside the worktree. Anchors are checked for regular-file availability; only the fixed sidecar is read by this endpoint. General conversations cause no anchor-path IO. Valid inline anchors require a selectable file and current modified content. There is **no content-staleness detection or anchor migration** when content or comparison refs change.

Existing file events and SSE reconnects reload conversations; unchanged payloads do not remount the editor. External sidecar edits refresh without a reload: the watcher always observes `.canopy/` and `.canopy/comments.yaml`, even when they are gitignored and regardless of **Ignore .gitignore paths**. Atomic sidecar replacement is handled like other add/change/unlink events. A malformed or partial write keeps the last valid conversation on display with a visible warning, and the next valid write clears it. A missing sidecar is a valid no-threads state, not a warning. Edited ignore rules still require restarting Canopy per the README.

## Public Monaco integration and filesystem limits

File and Diff share a public `changeViewZones` adapter with `updateThreads` and `revealThread` controllers. Anchors remain exact and unclamped; reveals target the selected article's live position, not the entire code range. Public `updateOptions({folding: false})` disables manual code folding while inline comments are present; no hidden-area or private folding API is used. Hunk navigation retains its separate public `onDidUpdateDiff` subscription. Automated fake-seam checks do not replace the USER's native visual/accessibility evaluation before a Monaco upgrade.

The reveal APIs were checked against the shipped **Monaco 0.45.0** [public declarations](https://unpkg.com/monaco-editor@0.45.0/monaco.d.ts) and [CodeEditorWidget source](https://unpkg.com/monaco-editor@0.45.0/esm/vs/editor/browser/widget/codeEditorWidget.js): `getTopForPosition(lineNumber, column): number`, model `getLineMaxColumn(lineNumber): number`, `getOption(EditorOption.lineHeight)`, `getScrollTop(): number`, `setScrollTop(newScrollTop, scrollType?)`, `getLayoutInfo(): EditorLayoutInfo` and `render(forceRedraw?)`. `setScrollTop` defaults to immediate scrolling; `render()` flushes current rendering synchronously. Layout height excludes the horizontal scrollbar when computing the usable viewport. In this version `getBottomForLineNumber` queries column 1, so it is unsuitable for the bottom of a wrapped model line: the adapter instead queries the last column and adds the current line height. It never probes a synthetic next line at EOF.

The public `IViewZone.onDomNodeTop(top)` callback supplies scroll-relative zone positioning ([view-zone source](https://unpkg.com/monaco-editor@0.45.0/esm/vs/editor/browser/viewParts/viewZones/viewZones.js)). Native offscreen zones are hidden, so reveal first exposes the zone and renders it, reconciles its measured rail height, then combines the current zone top with the selected article's `getBoundingClientRect()` offset inside the owned zone DOM. Measurements are refreshed for every reveal; no code-range centering, cursor manipulation, private APIs or persistent scroll subscriptions are used.

The rail explicitly sets public **`IViewZone.ordinal: -1`**. In Monaco 0.45.0, [lineAlignment.js](https://unpkg.com/monaco-editor@0.45.0/esm/vs/editor/browser/widget/diffEditor/lineAlignment.js) constructs original/modified alignment and inline deleted-code zones without `ordinal` or `afterColumn`; [viewZones.js](https://unpkg.com/monaco-editor@0.45.0/esm/vs/editor/browser/viewParts/viewZones/viewZones.js) assigns them the default ordinal **10000**. [LinesLayout](https://unpkg.com/monaco-editor@0.45.0/esm/vs/editor/common/viewLayout/linesLayout.js) orders same-view-line whitespace by ascending ordinal, independently of insertion time. Thus the single grouped comment rail comes first, immediately below the anchor, even at EOF or when asynchronous [diff-zone replacement](https://unpkg.com/monaco-editor@0.45.0/esm/vs/editor/browser/widget/diffEditor/utils.js) inserts tall native zones later. Native zones and their heights/models are not modified; native alignment continues accounting for the rail's height. Offscreen zero-height DOM measurements are ignored, retaining the previous rail height until it is visible. Recheck these ordering contracts and the manual large-deletion/alignment scenarios before upgrading Monaco.

The loader checks components with `lstat` (including dangling links) and opens the final sidecar with no-follow, nonblocking flags and a regular-file check. As with other local filesystem paths, it does not provide a hostile concurrent ancestor-directory mutation sandbox; do not run Canopy over an adversarial filesystem changing path components during a read.

## Save, reload and conflict demo (USER only)

See [review-comments.md](review-comments.md) for the contract. In a disposable registered worktree **without** a `.canopy/` directory:

- Open a file in File, inline Diff and side-by-side Diff. Hover the gutter beside a line: a `+` should appear in the glyph margin. Click it, or put the cursor on a line and press `c`. A composer opens below that line. Check Tab/Shift+Tab, focus, screen-reader label and typing without editor shortcuts firing.
- Range: select several modified-side lines (drag, or Shift+arrows) and click the `+` beside one of them, or press `c`. The composer's label reads "lines N-M" and it opens below the last selected line; a selection ending at column 1 of a later line stops before that line. Save and reload: the conversation stays below the last line and `comments.yaml` has `line_range: {start: N, end: M}`. Clicking the `+` on an unselected line comments on that line only. In inline Diff, deleted-line (original-side) selections must offer no composer and never become a modified-side range.
- Save a comment: it appears in the rail below the line as a user message. Reload the page: it remains. `.canopy/comments.yaml` now exists; Whether `git status` lists it depends only on your own ignore rules; Canopy must not have changed `.gitignore` or `.git/info/exclude`. Other worktrees must show nothing.
- Conflict: with the page open, change the sidecar externally (for example append a thread in an editor and save). Then save a new comment in Canopy: you must see a visible error that the comments changed, the composer must keep your text, and the new external thread should appear. Saving again then succeeds.
- Corrupt `comments.yaml` (for example `threads: [`) and save: expect a refusal and the file left as is.
- Deleted files and the original side must offer no composer. Long comments, wrapping, and a draft surviving a live file update (edit the file on disk while the composer is open) should be checked too.

## Live refresh demo (USER only)

Agents do not browser-verify this. In a disposable registered worktree whose `.gitignore` ignores `.canopy/`, with **Ignore .gitignore paths** both on and off, select the worktree and open `public/app.js`, then change the sidecar from a terminal using the atomic temp-file-and-rename workflow in [review-comments.md](review-comments.md):

- **Message:** copy `docs/fixtures/comments.yaml` to `.canopy/comments.yaml` (via a temp file and `mv`). Threads appear without a reload. Append an `author: agent` message to a thread the same way: it shows in chronological order, and the thread stays unresolved.
- **Resolution:** set `resolved: true` on a thread while adding an agent response. It switches to the grey, struck-through **Resolved** styling. Set it back to `false` and confirm it reopens.
- **Recovery:** write `threads: [` directly to the file. The last valid conversation stays visible with a warning. Then write valid YAML: the warning clears. Remove the file: no threads and no warning.
- **Isolation:** with two worktrees holding different sidecars, switch between them while editing either; no conversation from one appears in the other.
